# ARPINIA ODYSSEY — SYSTEM ARCHITECTURE

Version: 1.1

---

# 1. ARCHITECTURAL PRINCIPLE

**ALGORITHM-FIRST, AI-ASSISTED.**
The LLM is strictly downstream of the Evidence JSON. The deterministic pipeline owns the truth.

---

# 2. HIGH-LEVEL ARCHITECTURE & BOUNDARIES

**1. NEXT.JS FRONTEND (Public)**
- Renders maps, ranks, and reports. Consumes APIs. No scientific logic.

**2. FASTAPI BACKEND (Protected)**
- Orchestrates investigation, handles auth, and manages state.

**3. CORE INVESTIGATION ENGINES (Internal Services)**
- **AI/CV Engine**: PyTorch/Rasterio for SAR segmentation.
- **Drift Engine**: OpenDrift for backward trajectories.
- **AIS Engine**: Spatiotemporal DB queries.
- **Attribution Engine**: Deterministic evidence aggregation.

**4. DATABASE (Private)**
- PostgreSQL + PostGIS. Stores investigation truth.

**5. EVIDENCE JSON (Contract)**
- The canonical structured output generated by the Attribution Engine.

**6. LOCAL LLM (Internal Service)**
- Strictly downstream. Consumes Evidence JSON. Outputs human-readable interpretations. Cannot access database or alter scores.

**7. REPORT ENGINE**
- Combines Evidence JSON + LLM Interpretation to render PDFs.

---

# 3. DEPLOYMENT & SECURITY

- No exposure of DB, Redis, or internal models to the public internet.
- Local LLM access remains entirely server-side.
- Robust validation on all payloads.
